# SecureDev AI - System Architecture

## Overview

SecureDev AI is a RAG-based chatbot for secure software development.

It answers questions using FastAPI and OWASP documentation.

## Main Components

- Frontend: Streamlit
- Backend: FastAPI
- Vector Database: ChromaDB
- Knowledge Sources: FastAPI and OWASP documentation
- Language Model: Gemma 3 4B via Ollama
- Embedding Model: ChromaDB default embedding model

## Document Processing Pipeline

1. Collect documentation files.
2. Clean and process Markdown text.
3. Split documentation into smaller chunks.
4. Split Python examples by function and class boundaries.
5. Generate embeddings and store chunks in ChromaDB.
6. Save source filenames and chunk indices as metadata.

## RAG Workflow

1. The user submits a question through Streamlit.
2. Streamlit sends the question, selected source, and conversation history to FastAPI.
3. ChromaDB retrieves relevant document chunks.
4. Retrieved Python functions are preserved as original code examples.
5. Ollama generates an explanation using the retrieved context.
6. FastAPI returns the answer, source references, and available code examples.
7. Streamlit displays the response and stores it in the chat history.

## API Design

### GET /

Returns a welcome message.

### POST /chat

Accepts a question, optional knowledge source, and conversation history.

Example request:

    {
      "question": "What is JWT?",
      "source": "fastapi_oauth2_jwt.md",
      "history": []
    }

The source can be:

- `all`
- `fastapi_oauth2_jwt.md`
- `owasp_authentication.md`

Example response structure:

    {
      "answer": "Answer based on documentation.",
      "sources": [
        {
          "file": "fastapi_oauth2_jwt.md",
          "chunk_index": 9
        }
      ],
      "code_examples": []
    }

## Conversation History

The application uses recent conversation messages to help interpret follow-up questions.

Streamlit stores messages during the session and sends previous messages to FastAPI.

## Original Code Examples

Python implementation examples are indexed separately from Markdown text.

For code-related questions, the system can provide explanations generated by Gemma while preserving original retrieved Python functions.

These source excerpts may require additional imports and definitions.

## Testing

Pytest is used to check API request validation, conversation history forwarding, Python code chunking, and original code preservation.

## Limitations

- Ollama must be available locally.
- Answers are limited by the indexed documentation.
- AI-generated explanations may contain inaccuracies.
- Retrieved source code excerpts are not necessarily standalone applications.
